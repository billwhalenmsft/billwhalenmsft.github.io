I opened my demo tenant this week and found four new plugins already switched on in Copilot Cowork: Microsoft Dataverse, Business apps (preview), Sales and Service. In a demo tenant, that's fun. In a production tenant, each one is a decision about who can read and change customer records, and through what. Here's what each plugin does, how an admin turns it on, and what changes for your CRM, whether that's Dynamics 365, Salesforce or both.

The short version

  • Cowork can now work directly with your CRM records: reading accounts, opportunities and cases, and proposing updates that a person approves.
  • Nothing turns on by itself. An admin installs each plugin in the Microsoft 365 admin center under Agents > Tools > Plugins, for everyone or for specific groups.
  • Your existing security model still decides what each person sees and can change. Review it before you switch anything on, not after.
  • Salesforce customers get a different setup. The Dynamics 365 plugins read and update Dynamics 365. For Salesforce, the documented routes today are CRM-agnostic sales skills, the Salesforce Copilot connector for search, and the Sales agent.

The first three are for doing work in business data. The Dataverse plugin is for building on it. Microsoft's guidance is to try the Dataverse plugin in a sandbox or developer environment rather than production.

How to turn them on

  1. Confirm Cowork access. Users need Microsoft 365 Copilot, and Cowork access is granted through a spending policy in the Microsoft 365 admin center. That policy is an access control as well as a budget.
  2. Install the plugin. In the Microsoft 365 admin center, go to Agents > Tools > Plugins, select the plugin, choose Installed for (All users, or Specific users and groups), then install. Start with a pilot group.
  3. Check the app-side prerequisites.
    • Dynamics 365 Sales: users need a Sales Enterprise or Sales Premium license; the Dataverse MCP server must be enabled for the environment; and the Copilot Cowork setting must be on in the Sales agent admin settings.
    • Business apps and Dataverse: each user connects the plugin in Cowork > Customize and signs in. For Dataverse, they also enter the environment URL.
  4. Users switch them on in Cowork > Customize. On first use, Cowork asks which Dynamics 365 environment to use and remembers the choice.

The impact: what actually changes

1. Cowork moves from reading about the customer to updating the customer record.
These plugins can propose real changes: update an opportunity, create a task, reassign an account, escalate a case. Microsoft's design is that Cowork proposes and a person approves each change. That gate is real, but it shifts the risk to the approver. A rushed "approve" is now a CRM update.

2. Security roles become your AI policy.
Cowork only sees and does what the signed-in person can already see and do. That's good news if your roles are tight. If you've been relying on "nobody would ever find that view", an assistant that can search across tables and environments will find it. Review roles, field security and environment access first.

3. Turning a plugin on is an access decision, not a feature flag.
When an admin deploys a plugin to the whole organization, users can't remove it, although they can switch it off in their own conversations. Use security groups, start with a pilot, and decide who owns approvals for each plugin.

4. It runs on consumption.
Cowork usage draws Copilot Credits. Set spending limits and alerts before broad rollout, and remember that someone in a Cowork spending policy has access no matter how small the limit is.

5. More environments mean more ways to pick the wrong one.
Cowork can see every environment you can, including test and production. Teach people to check which environment Cowork is using, and keep makers on the Dataverse plugin in sandboxes.

6. Two kinds of CRM get two different experiences.

A sensible first 30 days

  1. Pick one team and one process, such as account prep for quarterly business reviews or case triage for one queue.
  2. Review security roles and environments for that team.
  3. Set a Cowork spending policy and alerts for the pilot group.
  4. Install only the plugin that process needs, for that group only.
  5. Agree who approves CRM changes, and spot-check approved changes weekly.
  6. Expand only after the first process works and the audit trail looks right.

The bottom line

These plugins turn Cowork from a smart reader of email and documents into a colleague that can work in your CRM. Microsoft has built in the right safeguards: admin-controlled installs, your existing permissions, and a person approving every change. Your job is to make sure the permissions and the approvers are ready before you switch them on.
